# 폭염 모빌리티 적응 격차와 무더위쉼터 입지 선정

KT 생활이동 데이터와 기상청 관측 자료로 폭염일에 **내국인 · 단기 체류 외국인(관광객) · 장기 체류 외국인**의 이동이 어떻게 달라지는지 추정하고, 그 결과를 행정동 클러스터링과 공간통계로 연결해 무더위쉼터 신규 입지를 제안한 프로젝트입니다.

경희대학교 머신러닝 기초 및 응용 2조 · 오동근, 이유진, 오동진, 김민섭

- 📊 발표자료: [`reports/발표자료.pdf`](reports/발표자료.pdf)
- 📝 결과보고서: [`reports/결과보고서.pdf`](reports/결과보고서.pdf)

## 핵심 결과

| 통제 단계 | 내국인 | 단기 외국인 | 장기 외국인 |
|---|---|---|---|
| 단순 비교 | +8.09% | +4.56% | −4.41% |
| + 강수 | +5.41% | +3.51% | −7.61% |
| + 요일 | +2.59% | +1.98% | −8.09% |
| **+ 시즌 (매칭 완성)** | **−3.01%** | **−0.90%** | **−3.66%** |

- 단순 비교에서는 "폭염일에 사람이 더 돌아다닌다"는 결론이 나오지만, 시즌·요일·강수 교란을 매칭으로 걷어내면 부호가 뒤집힙니다.
- 장기 외국인은 내국인만큼 이동을 줄이고 **단기 관광객만 거의 줄이지 않습니다** (내국인–단기 격차 2.11%p, p < 0.0001). 적응 격차는 국적이 아니라 그 도시의 여름을 겪은 경험의 문제입니다.
- 행정동 256개를 4피처 K-means(k=3, 실루엣 0.452)로 나눠 **고노출·비탄력형** 43개 동을 식별했고, Moran's I(0.319)·Gi* 핫스팟과 필터링으로 **신규 쉼터 우선 입지 36개 동**(강남·서초·송파 27개)을 도출했습니다.

## 방법

1. **데이터**: KT 서울 생활이동(시간대별 도착, 원천 약 34GB), 기상청 ASOS 서울(108) 시간자료, 서울시 무더위쉼터 4,083개소, 주요 관광지 121곳 폴리곤, 행정동·자치구 경계
2. **폭염일 정의**: 일 최고 체감온도(KMA 여름철 공식) 33℃ 이상 — 2023~2025년 여름 276일 중 69일
3. **매칭 기반 준실험 설계**: 폭염일마다 같은 자치구 · 같은 요일 · ±14일 이내 · 비폭염 · 맑은 날을 대조일로 짝지어 변화율 = (폭염일 − 대조일 평균) ÷ 대조일 평균 × 100
4. **강건성**: 매칭 윈도우 ±7 / ±14 / ±21일 민감도, 시간대별 매칭
5. **행정동 클러스터링**: 피처셋 × 알고리즘(K-means·GMM·Ward) × k × 원공간/PCA 스윕 후, 점수를 부풀리는 PCA·공선 피처 구성을 배제하고 원공간 4피처(노출·회피·야외관광커버·상업관광커버) 채택. 80% 부트스트랩 ARI k=2 0.93 / k=3 0.88
6. **공간 분석**: 전역 Moran's I, Getis-Ord Gi* 핫스팟 → 기존 쉼터 0.8km·대형 냉방시설·저노출 동 필터

## 저장소 구성

```
구현코드_전체.py        보고서 흐름 15단계를 한 파일로 정리한 최종 구현 (전처리 → 매칭 → 동 피처 → 클러스터링 → 입지)
requirements.txt        최종 구현 의존성
src/                    공공 API 수집·전처리 모듈 (초기 파이프라인)
  api_client.py         tenacity 재시도 + 디스크 캐시 GET 헬퍼 (서비스키는 캐시 키에서 제외)
  collectors/           기상청 ASOS 시간자료 수집기 등
  preprocessing/        생활인구·기상 결합 패널 생성
clustering/             행정동 군집 탐구 (피처셋 스윕, 최종 채택본, 결과표, 탐구 기록)
docs/                   실행 계획서, 피처 사전, 인증키 발급 안내, AI 코딩 에이전트용 컨텍스트(CLAUDE.md)
figures/                주요 결과 그림
reports/                발표자료 · 결과보고서
```

## 실행

```bash
pip install -r requirements.txt
python 구현코드_전체.py                    # 03~15단계 (전처리 산출 parquet 필요)
RUN_PREPROCESS=1 python 구현코드_전체.py   # 01~02b 원천 데이터 전처리부터
```

- 원천·가공 데이터는 용량과 재배포 라이선스 때문에 저장소에 포함하지 않았습니다. 코드는 같은 위치(또는 한 단계 위)의 `데이터/` 폴더를 자동으로 찾습니다.
- 공공 API 수집기를 쓰려면 `.env.example`을 `.env`로 복사해 인증키를 채우세요 (발급 절차: [`docs/api_keys.md`](docs/api_keys.md)). `.env`는 커밋되지 않습니다.
