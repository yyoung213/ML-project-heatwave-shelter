## Project domain

머신러닝 기말 프로젝트: **서울 폭염·미세먼지 상황에서 단기체류 외국인 관광객의 노출 격차(exposure gap) 분석**.

- 분석 단위: **행정동(~425개) × 일자 × 1시간 시간대**
- 대상 기간: 코로나 이후 정상 연도 3개 (여름 6~8월, 미세먼지 축 추가 시 봄 3~5월 병행). 구체 연도는 D-0 단계의 사전 EDA에서 확정.
- 코로나기(2020–2021) 제외 필수. 2018 극단폭염은 포함 시 별도 표기.

## Core concept — 노출 격차 지표 (the central derived metric)

```
gap = (외국인 실제 / 외국인 평년) − (내국인 실제 / 내국인 평년)
```

- "평년"은 **동별 같은 요일·시간대 중앙값**. 동 간 규모 차이와 집단 간 규모 차이를 정규화로 흡수하는 것이 분석의 핵심.
- `gap > 0`이면 "내국인은 빠졌는데 외국인은 남았다" → 폭염/고농도 시 노출 격차 발생.
- 집단별 원시 체류수가 아니라 이 정규화/편차 값을 종속변수로 써야 한다. 원시 카운트로 회귀하면 동·집단 규모에 결과가 좌우된다.

## Planned pipeline (4 phases)

데이터 흐름은 단방향: **수집(raw) → 전처리(processed) → EDA → 분석/예측**.

1. **Phase 1 — 수집** (`raw/` 디렉터리)
   - 수동 FILE 다운로드: 서울 생활인구 3종 (단기외국인 A-1, 내국인 A-2, 장기외국인 A-3). **유일한 수고 지점** — 시즌 수만큼 반복.
   - API 자동: 무더위쉼터, 문화행사, 기상청 ASOS/특보, 에어코리아 PM, 공휴일.
   - 정적 1회: 행정동 경계, 시설 좌표.
   - 원본은 가공 전 보관 (재현성).

2. **Phase 2 — 전처리** → `processed/analysis_dataset.parquet`
   - **공간 조인이 비자명한 부분**: 생활인구는 행정동 기준, 기상/미세먼지는 관측소/측정소 기준. 행정동 중심좌표 기준 최근접 관측소 또는 자치구 대표값으로 매핑. 측정소 밀도 낮은 곳은 자치구 단위 보간.
   - 행정동 코드는 **연도별 통폐합**이 있음 → 기간 내 코드 통일 필요.
   - 생활인구 3명 이하 `*` 마스킹 셀: 결측 플래그 + 0~3 구간 대치 규칙을 분석 전체에 일관되게 적용.
   - 파생: 체감온도(열지수), 폭염더미, PM 등급, 강수, 요일·공휴일·성수기·행사 더미.
   - 산출 테이블 그레인: `(행정동코드, 일자, 시간대)` 행, 컬럼은 집단별 체류·정규화값·기상·미세먼지·통제·`gap`.

3. **Phase 3 — EDA**
   - **목적은 시각화가 아니라 분석 가능성 검증.** 특히 이벤트 표본(폭염일수)이 충분한지 먼저 본다 → 대상 연도 확정 근거.
   - 교란 점검 필수: 폭염일이 성수기·주말·행사일과 얼마나 겹치는지 (공선성 위험).

4. **Phase 4 — 분석**
   - **진단 모델**: 집단별 기상 탄력성 비교. 해석용은 패널 고정효과 회귀(동·연도 FE), 비선형/상호작용용은 LightGBM + SHAP. 내국인 모델 vs 외국인 모델의 계수/SHAP 비교가 격차 입증의 핵심.
   - **운영 모델**: 폭염/고농도 예보일의 동·시간대 외국인 체류 예측. 시간 순 분할로 검증, **미래 정보 누수 금지**(예: 평년 중앙값 계산 시 검증 기간 포함 금지).
   - 산출: 핫스팟 지도, 무더위쉼터 미스매치 오버레이, 운영 예측 스코어.

## Research framing (중요)

연구 질문은 **"외국인은 둔감한가?"(예/아니오)가 아니라 "노출 격차는 어디서, 얼마나 발생하는가?"(측정형)**.
- 가설과 반대로(외국인도 회피) 나와도 "회피 동선 지도"로 산출물 전환 가능. 분석/모델링 결정 시 이 측정형 프레이밍을 깨지 않는 방향으로 진행.
